# Техническое задание
**Проект:** Трекер расходов. **Заказчик:** MyБюджет (Терехов). **Автор:** Кулешов, группа: 11ТЭС.
**Версия документа:** 1.0. **Дата:** 19.11.2026.
## Назначение и функции
Система для учёта личных покупок (основание — `docs/requirements.md`). Функции: FR-1 (добавление), FR-2 (список и карточка), FR-3 (поиск и фильтр), FR-4 (статусы), FR-5 (удаление).
## Интерфейс
- Одно окно Tkinter: поля ввода (название, цена, дата), кнопки («Добавить», «Следующий статус», «Удалить»), поиск, фильтр по статусу и список записей.
- Ошибки: окно `messagebox.showwarning` при пустых полях или цене ≤ 0.
## Данные и реализация
- Стек: Python 3 + Tkinter. Хранение: список словарей в памяти (`purchases = []`).
- Поля словаря: `id` (номер), `date` (дата), `title` (название), `price` (число > 0), `status` (по умолчанию «Запланировано»).
- Переходы статусов: только «Запланировано» → «Оплачено» → «Проверено».
## Приёмка
- AT-1 (FR-1): корректный ввод → запись добавлена в список.
- AT-2 (NFR-2): пустое поле или буквы в цене → предупреждение, запись не создана.
- AT-3 (FR-3): ввод в поиск / выбор статуса → список отфильтрован.
- AT-4 (FR-4): перевод «Запланировано» → «Оплачено» работает; перескок в «Проверено» запрещён.
- AT-5 (FR-5): удаление → отмена оставляет запись, подтверждение удаляет.
- AT-6: перезапуск приложения → список пуст.
- Условия сдачи: пройдены AT-1 — AT-6, продукт принят заказчиком (Терехов).
